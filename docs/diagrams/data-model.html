Data model

One Cloud SQL instance per bounded context — no cross-service joins. These tables live in different databases; the relationships below are enforced by event contracts, not foreign keys, except where a table is genuinely owned and queried within one service.

Relationships

  • Instruments → Quotes — one instrument, many quotes over time (append-only, partitioned by day)
  • Instruments → Orders — one instrument, many orders
  • ClientAccounts → Orders — a client places many orders
  • Orders → Trades — one order, one or more fills
  • Trades ⇢ Positions — Positions is rebuilt from Trades via event projection, not a live foreign key
  • ClientAccounts → Positions — net exposure per client per instrument
  • ClientAccounts → StrategyAssignments — which IFxStrategy a client gets, per instrument class
High-write tables (Quotes, Orders) use read replicas for blotter queries so the transactional path never competes with UI polling. See the design doc. Part of BEX.
